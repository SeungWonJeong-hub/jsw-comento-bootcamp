# 2차 업무 — Unit Test 구성 및 2D → 3D 변환

**달 사진 두 장으로 지형의 높낮이를 복원한다.** 착륙 지점을 고르려면 어디가
평평한지 알아야 하는데, 사진에는 색만 있고 높낮이가 없다.

```
사진 2장  →  시차 d  →  깊이 맵 Z = f·B/d  →  3D 포인트 클라우드
             ↑ 두 사진에서 밀린 픽셀 수      ↑ 그것을 3D 로 바꾼다
```

| | 값 |
|---|---:|
| 대상 | 티코 크레이터 (기복 **5.376 km**) |
| 고도 오차 중앙값 | **0.0303 km** (기복의 0.56%) |
| 90 퍼센타일 | 0.0822 km |
| 덮은 셀 | **76.4%** |
| 포인트 클라우드 | 313,063 점 |
| — 사진 한 쌍만 쓰면 | 0.0361 km · 63.2% |

정답은 **LRO LOLA 레이저 고도계로 실제 측정된 고도**다. 근사로 만든 기준이
아니다. 시차 1픽셀이 0.45 km 를 바꾸는 촬영 조건에서 오차가 0.0303 km 이므로
**부화소까지 맞춘 셈**이다.

**수렴각이 다른 네 쌍을 합쳐 얻은 값이다.** 한 쌍만 쓰면 0.0361 km 에 63.2% 를
덮는데, 합치면 정확도와 덮는 범위가 **함께** 좋아진다(7-8절).

- 고도 모델: LRO LOLA 0.118 km/화소 (USGS Astrogeology, 공개 자료)
- 테스트: pytest **56개** 통과 (고도 모델이 없으면 3개 skip)

## 2. 촬영을 어떻게 세웠는가

궤도에서 찍은 원본 영상으로 곧장 스테레오를 돌리려면 카메라 자세 커널과 지도
투영을 다루는 전용 도구 체계가 필요하다. 그 준비만으로 며칠이 간다. 대신
**이미 레이저로 측정된 고도 모델에서 출발**한다.

고도를 3D 점으로 펴고, 자세를 아는 카메라 두 대로 다시 찍은 뒤, 그 두 장으로
고도를 복원해 원래 값과 비교한다.

> **기하는 실제 달이고 밝기는 렌더링이다.** 그림자와 표면 반사 특성은 실제
> 영상과 다르다. 이 실험이 검증하는 것은 **촬영 기하와 정합**이지 촬영 자체가
> 아니다. 착륙 위험 탐지 연구에서 실제로 쓰는 방식이지만, 이 한계는 분명히
> 해야 한다.

**두 카메라는 같은 지점을 바라본다(수렴 촬영).** 실제 궤도 스테레오도 나란히
두 대를 놓는 것이 아니라, 지나가며 앞뒤로 기울여 같은 지역을 두 번 찍는다.

```
R1, t1 / R2, t2 = 두 촬영 지점의 자세
① 상대 자세   R = R2 · R1ᵀ,   t = t2 − R · t1
② 베이스라인  B = 2 · H · tan(수렴각 / 2)
③ 정렬·정합   stereoRectify(R, t) → StereoSGBM → 시차 d
④ 깊이        Z = f · B / d
⑤ 3D 좌표     X = (u−cx)·Z/f,  Y = (v−cy)·Z/f
```

| 기호 | 뜻 | 값 |
|---|---|---:|
| H | 촬영 고도 | 59.2 km |
| 수렴각 | 두 시선이 벌어진 각 | 15° |
| B | 베이스라인 | 15.6 km |
| f | 초점거리 | 500 px |
| — | 시차 1픽셀이 바꾸는 Z | 0.45 km |

**초점거리를 고도에서 유도한다.** `f = H / 화소 크기`로 두면 영상 화소와 지형
화소가 1:1 이 된다. 고도를 상수로 박으면 고도 모델이 바뀔 때(합성 0.005 km,
LOLA 0.118 km) 시차가 화면을 넘거나 몇 픽셀로 쪼그라든다.

RMSE 가 0.175 km 로 큰 것은 크게 틀린 소수의 화소가 끌어올린 값이다. 중앙값과 함께
봐야 한다.

## 4. 수렴각 — 정밀도와 덮는 범위가 맞바뀐다

두 시선이 벌어진 각이 이 실험의 중심 파라미터다. 각이 크면 삼각형이 뚱뚱해져
거리가 정밀해지지만, 두 영상이 서로 달라 보여 같은 지점을 찾기 어려워진다.

| 수렴각 | 베이스라인 | 시차 1px = Z | 값이 나온 픽셀 | Z 오차 중앙값 |
|---:|---:|---:|---:|---:|
| 10° | 10.4 km | 0.677 km | 78.7% | 0.0583 km |
| **15°** | **15.6 km** | **0.45 km** | **69.3%** | **0.0345 km** |
| 20° | 20.9 km | 0.336 km | 60.6% | 0.0338 km |
| 30° | 31.7 km | 0.221 km | 43.8% | 0.0247 km |

**10°에서 30°로 벌리면 오차가 0.0583 → 0.0247 km 로 줄지만, 값이 나온 픽셀이
78.7 → 43.8% 로 떨어진다.** 한 쌍만 쓴다면 여기서 타협해야 한다.

**그런데 타협하지 않아도 된다.** 각도마다 덮는 곳이 다르므로 여러 각도를 합치면
둘 다 얻는다. 7-8절이 그 측정이다.

`outputs/01_tradeoff.png` 의 왼쪽 그래프에서 두 선이 반대로 가는 것이 이것이다.

결과를 지배한다.**

## 6. Unit Test 설계

과제 예시의 테스트(p.14)는 출력 크기와 자료형만 확인한다. 그것만으로는 수식이
틀려도 통과한다. **손으로 답을 낼 수 있는 조건**을 만들어 숫자까지 대조했다.

| 갈래 | 예시 | 검증 방식 |
|---|---|---|
| **해석해** | 평지를 수직으로 보면 깊이 = 촬영 고도 | 1e-6 이내 |
| | 기울기 tan(t) 사면의 법선 | 1e-9 이내 |
| | 태양이 머리 위면 밝기 = albedo | 1e-9 이내 |
| **불변식** | `B = 2·H·tan(수렴각/2)` | 상대오차 1e-12 |
| | `p_j = R·p_i + t` 가 실제로 성립 | 1e-12 이내 |
| | B와 d를 함께 2배 하면 Z 불변 | 스케일 모호성 |
| **왕복** | 깊이 맵 → 3D → 고도가 원래 값과 같은가 | 0.002 km 이내 |
| **전체** | 렌더링→정렬→정합→깊이 를 한 번에 | 시차 0.5 px 이내 |
| **회귀** | 렌더링한 두 장이 `f·B/d` 에서 겹치는가 | 실제 결함을 잡은 테스트 |
| | 수직 시점 두 대가 오른쪽을 뒤집지 않는가 | 두 번째 결함 |
| | 지형이 카메라보다 높으면 멈추는가 | 세 번째 결함 |
| | 무늬가 없는 곳을 걸러내는가 | 네 번째 결함 |
| **경계** | 화소 크기 0, 수렴각 90°, 크기 불일치 | 예외 처리 |

**독립적인 경우는 `@pytest.mark.parametrize` 로 나눈다.** 잘못된 수렴각 네 가지,
잘못된 화소 크기 두 가지가 그렇다. 한 번에 루프를 돌면 첫 실패에서 멈춰
나머지가 실행되지 않고 어느 값에서 깨졌는지도 이름에 안 남는다.

## 7. 검토에서 찾아 고친 것

파이프라인을 다섯 갈래로 훑었다 — 기하 항등식, 수치 안정성, 데이터 흐름,
재현성, 교란 실험. **일곱 건이 나왔고 전부 고쳤다.**

### 7-1. 렌더링이 시차를 밀어내고 있었다

처음 실행에서 Z 오차가 **1.245 km** 나왔다. 분해능이 0.45 km/px 인데 2.8 px 이라
잡음치고는 크고, 무엇보다 **오차가 한쪽으로 치우쳐** 있었다(부호 있는 오차 평균
−1.101 km).

| 확인한 것 | 결과 |
|---|---|
| 정렬 창 보정이 두 카메라의 주점을 어긋내나 | 아님 — 같은 양만큼 옮긴다 |
| `Z = f·B/d` 가 실제 투영과 맞나 | **정확히 일치** |
| 정렬 좌표계에서 직접 렌더링하면 | **오프셋 0.0 px** → 기하와 기준 깊이는 옳다 |
| `alpha` 를 바꾸면 오프셋이 | 2.0 / 2.6 / 3.6 → **초점거리에 비례** (각도 0.3°) |
| 점 번짐(splat)을 끄면 | +2.6 → **+0.6 px** |
| 화소마다 광선을 쏘면 | **−0.10 px** |

원인은 렌더러였다. 점을 화소에 던져 그리면서 위치를 **반올림**하는데, 그 오차가
표면 기울기 방향으로 쏠린다. 수렴 촬영의 두 카메라는 서로 반대로 기울어 있으므로
좌우가 반대로 쏠리고, 그 차이가 그대로 시차 치우침이 된다. 점 번짐은 깊이 버퍼에
3×3 최소값 필터를 거는 셈이라 표면을 카메라 쪽으로 당겨 이를 키웠다.

번짐은 **빈 화소를 메우는 데만** 쓰도록 바꾸고, 흩뿌리기 자체를 **화소마다
광선을 쏘아 지형과 만나는 점을 이중선형으로 찾는 방식**으로 교체했다.
**Z 오차 1.245 km → 0.066 km.**

### 7-2. 수직 시점 두 대의 오른쪽이 뒤집혔다

카메라 자세를 만들 때 "위쪽"을 수직(0,0,1)으로 뒀다. 아래를 내려다보는 카메라는
시선이 거의 −Z 라 그 기준과 나란해지고, 외적이 0 에 가까워져 영상의 오른쪽이
시선의 미세한 수평 성분으로 정해진다. **두 카메라의 상대 회전이 15°가 아니라
180°로 나왔다.** 수평 기준(북쪽)을 주어 고쳤다.

### 7-3. 깊이 탐색 구간을 잘못 잡았다

`고도 ± 기복`으로 잡았는데, 정렬된 카메라는 수렴각의 절반만큼 기울어 있어
**지형이 넓으면 Z 가 화면을 가로질러 크게 변한다.** 티코(75 km 폭)에서 Z 가
±5 km 흔들려 옳은 시차가 구간 밖으로 잘려 나갔다. 지형 경계 상자의 여덟
꼭짓점을 정렬 카메라로 옮겨 실제 Z 범위를 구하도록 고쳤다.

### 7-4. 광선이 수렴하지 않은 채 값을 내고 있었다

복원한 점이 실제로 고도장 위에 있는지 재 보니 화소의 **10%가 잔차 0.001 km 를 넘었고
최악은 0.3 km** 였다. 반복 횟수를 다섯 배로 늘려도 줄지 않았다 — 수렴이 느린
것이 아니라 **아예 수렴하지 않는 것**이었다. 지형 격자 밖으로 나간 광선이
가장자리 값으로 고정되어 진동한다.

반복 뒤 t 를 한 번 더 갱신하고, **마지막 갱신 폭이 화소 크기의 1/100 을 넘으면
값을 내지 않는다.** 잔차 최악 **0.3 km → 0.00004 km**, 0.001 km 초과 0%.

### 7-5. 무늬가 없는 곳에서 아무 값이나 내고 있었다

크게 틀린 화소(1 px 초과)의 평균 밝기가 **62** 로 전체 평균 **114** 보다 훨씬
어두웠다 — 크레이터 안쪽 그늘이다. 국소 대비(7×7 표준편차) 하한을 재 봤다.

| 대비 하한 | 값이 나온 화소 | Z 오차 중앙값 | 1 px 초과 |
|---:|---:|---:|---:|
| 0 | 72.0% | 0.0661 km | 0.99% |
| **2** | **69.4%** | **0.0649 km** | **0.69%** |
| 4 | 63.0% | 0.0633 km | 0.75% |
| 8 | 47.2% | 0.0609 km | 0.94% |

하한 2 는 화소를 2.6 %p 만 내주고 **크게 틀린 화소를 3분의 1 줄인다.**
`uniquenessRatio` 는 30 까지 올려도 지렛대가 되지 못했다(21 → 16.5%).

### 7-6. 시차가 정수 부근에 몰려 있었다 (픽셀 락킹)

시차 소수부를 세어 보니 정수 부근(±0.1 px)에 **49.3%** 가 몰려 있었다. 균일하면
20% 여야 한다. SGBM 부화소 보간의 알려진 성질이고, 이것이 깊이를 **+0.043 px
(약 0.019 km)** 치우치게 만들었다 — 당시 전체 오차 0.065 km 의 3분의 1 이다.

시차는 가로 방향이므로 **가로로만 늘려 정합한 뒤 되돌린다.**

| 배율 | 값이 나온 화소 | Z 오차 중앙값 | 정수 부근 | 시차 편향 |
|---:|---:|---:|---:|---:|
| 1× | 69.4% | 0.0649 km | 49.3% | +0.043 px |
| **2×** | **69.3%** | **0.0346 km** | **35.9%** | **+0.024 px** |
| 4× | 69.6% | 0.043 km | 40.9% | +0.028 px |

**2배에서 오차가 거의 절반이 되고 화소 손실은 없다.** 4배는 오히려 나빠진다 —
보간이 없는 정보를 만들어 내지는 못한다.

### 7-7. 여러 수렴각을 합치면 트레이드오프가 사라진다

4절에서 "정밀도와 덮는 범위를 동시에 얻을 수 없다"고 적었는데, **한 쌍만 쓸
때의 이야기**였다. 각도가 다르면 정합에 성공하는 곳도 다르다. 정밀한 각도는
좁고 촘촘하게, 넓은 각도는 넓고 성기게 덮는다.

각도마다 정렬 창의 크기가 달라 깊이 맵끼리는 화소 단위로 겹칠 수 없다. **지형
격자**가 모든 각도가 공유하는 유일한 좌표계이고, 만들려는 산출물 자체가 "격자
위의 고도"이므로 거기서 합친다. 가중치는 **1/분해능²** — 시차 1픽셀이 바꾸는
깊이가 그 각도의 정밀도이고, 오차가 거기 비례한다면 역분산 가중이 그 값이 된다.

| | 덮은 셀 | 오차 중앙값 | 90 퍼센타일 | RMSE |
|---|---:|---:|---:|---:|
| 10° 단독 | 72.0% | 0.0612 km | 0.1463 km | 0.138 km |
| 15° 단독 | 63.2% | 0.0361 km | 0.0933 km | 0.183 km |
| 20° 단독 | 54.8% | 0.0358 km | 0.0813 km | 0.206 km |
| 30° 단독 | 38.9% | **0.0261 km** | 0.0635 km | 0.265 km |
| **네 각도 융합** | **76.4%** | **0.0303 km** | 0.0822 km | **0.131 km** |

**어느 단독 각도보다 넓게 덮으면서, 30° 단독을 빼면 가장 정확하다.** 30°는
0.0261 km 로 정확하지만 38.9% 밖에 못 덮는다. RMSE 는 융합이 가장 좋다 — 크게
틀린 값이 걸러지기 때문이다.

**각도끼리 어긋나는 셀을 버리는 것이 신뢰도 역할을 한다.** 정답을 보지 않고
"믿을 수 없는 곳"을 가려낼 수 있는 단서다. 서로 다른 기하에서 본 값이 다르면
둘 중 하나 이상이 틀린 것이다. 90 퍼센타일 오차가 0.0872 → 0.0822 km 로 준다.
두 각도 이상이 값을 낸 셀이 66.3%, 세 각도 이상이 53.6% 다.

### 7-8. 다른 지역에서도 같은 결과가 나오는가

한 크레이터에 맞춰진 결과가 아닌지 확인하려고, 같은 설정 그대로 코페르니쿠스
크레이터(20.0°N, 3.6°W, 기복 5.659 km)에서 다시 돌렸다.

| | 티코 | 코페르니쿠스 |
|---|---:|---:|
| Z 오차 중앙값 | 0.0345 km | 0.0462 km |
| 시차 단위 | 0.08 px | 0.10 px |
| 기복 대비 | 0.64% | 0.82% |
| 값이 나온 픽셀 | 69.3% | 55.1% |

**정확도는 같은 수준이고 덮는 범위만 다르다.** 코페르니쿠스는 위도 20°N 이라
태양 고도가 달라 그늘이 더 넓다. 파라미터를 다시 고르지 않고 그대로 돌린 결과다.

## 8. 한계

- **밝기가 렌더링이다.** 기하는 실제 달이지만 그림자와 반사 특성은 실제 영상과
  다르다. 이 실험이 검증하는 것은 촬영 기하와 정합이다.
- **"대응이 없다"를 말할 수 없다.** 매처는 탐색 구간 안에서 반드시 무언가를
  고른다. 좌우에 **같은 영상**을 넣어도 화소의 21%가 값을 내고, 그중 96%가
  1 px 이상 틀린다(중앙값 3.34 km). 대비 관문을 걸어도 20%로 거의 줄지 않는다.
- **값이 나온 픽셀이 69.3% 다.** 나머지는 대부분 크레이터 안쪽 그늘로, 두
  사진에 같은 무늬가 보이지 않는 곳이다.
- **가림(occlusion)을 다루지 않는다.** 광선이 앞쪽 봉우리를 지나쳐 뒤쪽 지면에
  닿아도 그대로 받는다. 시선이 지면에 거의 수직이라 지금 조건에서는 문제가
  없지만, 수렴각을 더 키우면 확인이 필요하다.
- **고도 모델이 0.118 km/화소다.** 레이저 궤적을 격자로 편 것이라 매끈해서, 더 높은
  해상도 모델(LRO NAC DTM)보다 잔무늬가 적다.
- **촬영 자세를 정답으로 안다.** 우리가 정한 값이라 오차가 없다. 실제 궤도
  영상이라면 자세도 추정해야 하고, 그 오차가 결과를 흔든다.

## 9. 개선점 — 아직 안 한 것

과제 요청내용 3번("변환된 3D 이미지의 시각적 결과를 분석하고 개선점을 도출")에
대한 답이다. 검토에서 나온 것 중 **고칠 수 있는 것은 7절에서 전부 고쳤고**,
아래 둘만 남는다.

**① 픽셀 락킹을 더 줄인다.** 가로 2배 업샘플로 정수 부근 쏠림을 49.3 → 35.9%
까지 낮췄지만 여전히 균일(20%)보다 높다. 4배는 오히려 나빠졌다 — 보간이 없는
정보를 만들지는 못한다. 비용 곡선에 대칭 보간을 다시 얹거나 WLS 후처리를 쓰면
더 줄일 수 있다고 알려져 있는데, OpenCV 기본 배포에는 그 모듈이 없다.

**② 더 높은 해상도 고도 모델을 쓴다.** LOLA 0.118 km 는 레이저 궤적을 격자로 편
것이라 매끈하다. LRO NAC DTM(0.002~0.005 km/화소)을 쓰면 잔무늬가 많아져 정합이 쉬워질
것으로 보이지만, PDS 원본 포맷과 전용 도구 체계가 필요하다. **이 실험의 남은
빈 곳(23.6%)이 대부분 그늘이므로, 해상도보다 조명 조건이 다른 시점을 더 모으는
쪽이 먼저다** — 다만 그것은 실제 궤도 영상이 있어야 한다.
