# 2차 업무 — Unit Test 구성 및 2D → 3D 변환

**달 사진 두 장으로 지형의 높낮이를 복원한다.** 착륙 지점을 고르려면 어디가
평평한지 알아야 하는데, 사진에는 색만 있고 높낮이가 없다.

```
사진 2장  →  시차 d  →  깊이 맵 Z = f·B/d  →  3D 포인트 클라우드
             ↑ 두 사진에서 밀린 픽셀 수      ↑ 그것을 3D 로 바꾼다
```

| | 값 |
|---|---:|
| 대상 | 티코 크레이터 (기복 **5,376 m**) |
| Z 오차 중앙값 | **65 m** = 시차 **0.14 px** |
| 시차 0.5 px 이내 | **98.8%** |
| 지형 기복 대비 | 1.21% |
| 값이 나온 픽셀 | 69.4% |
| 포인트 클라우드 | 305,199 점 |

정답은 **LRO LOLA 레이저 고도계로 실제 측정된 고도**다. 근사로 만든 기준이
아니다. 시차 1픽셀이 450 m 를 바꾸는 촬영 조건에서 중앙값 오차가 65 m 이므로
**부화소까지 맞춘 셈**이다.

- 고도 모델: LRO LOLA 118 m/화소 (USGS Astrogeology, 공개 자료)
- 테스트: pytest **51개** 통과 (고도 모델이 없으면 3개 skip)

## 2. 촬영을 어떻게 세웠는가

궤도에서 찍은 원본 영상으로 곧장 스테레오를 돌리려면 카메라 자세 커널과 지도
투영을 다루는 전용 도구 체계가 필요하다. 그 준비만으로 며칠이 간다. 대신
**이미 레이저로 측정된 고도 모델에서 출발**한다.

고도를 3D 점으로 펴고, 자세를 아는 카메라 두 대로 다시 찍은 뒤, 그 두 장으로
고도를 복원해 원래 값과 비교한다.

> **기하는 실제 달이고 밝기는 렌더링이다.** 그림자와 표면 반사 특성은 실제
> 영상과 다르다. 이 실험이 검증하는 것은 **촬영 기하와 정합**이지 촬영 자체가
> 아니다. 착륙 위험 탐지 연구에서 실제로 쓰는 방식이지만, 이 한계는 분명히
> 해야 한다.

**두 카메라는 같은 지점을 바라본다(수렴 촬영).** 실제 궤도 스테레오도 나란히
두 대를 놓는 것이 아니라, 지나가며 앞뒤로 기울여 같은 지역을 두 번 찍는다.

```
R1, t1 / R2, t2 = 두 촬영 지점의 자세
① 상대 자세   R = R2 · R1ᵀ,   t = t2 − R · t1
② 베이스라인  B = 2 · H · tan(수렴각 / 2)
③ 정렬·정합   stereoRectify(R, t) → StereoSGBM → 시차 d
④ 깊이        Z = f · B / d
⑤ 3D 좌표     X = (u−cx)·Z/f,  Y = (v−cy)·Z/f
```

| 기호 | 뜻 | 값 |
|---|---|---:|
| H | 촬영 고도 | 59.2 km |
| 수렴각 | 두 시선이 벌어진 각 | 15° |
| B | 베이스라인 | 15.6 km |
| f | 초점거리 | 500 px |
| — | 시차 1픽셀이 바꾸는 Z | 450 m |

**초점거리를 고도에서 유도한다.** `f = H / 화소 크기`로 두면 영상 화소와 지형
화소가 1:1 이 된다. 고도를 상수로 박으면 고도 모델이 바뀔 때(합성 5 m,
LOLA 118 m) 시차가 화면을 넘거나 몇 픽셀로 쪼그라든다.

## 4. 수렴각 — 정밀도와 덮는 범위가 맞바뀐다

두 시선이 벌어진 각이 이 실험의 중심 파라미터다. 각이 크면 삼각형이 뚱뚱해져
거리가 정밀해지지만, 두 영상이 서로 달라 보여 같은 지점을 찾기 어려워진다.

| 수렴각 | 베이스라인 | 시차 1px = Z | 값이 나온 픽셀 | Z 오차 중앙값 |
|---:|---:|---:|---:|---:|
| 10° | 10.4 km | 677 m | 78.9% | 94.3 m |
| **15°** | **15.6 km** | **450 m** | **69.4%** | **64.9 m** |
| 20° | 20.9 km | 336 m | 60.8% | 57.7 m |
| 30° | 31.7 km | 221 m | 43.8% | 33.4 m |

**10°에서 30°로 벌리면 오차가 94.3 → 33.4 m 로 줄지만, 값이 나온 픽셀이
78.9 → 43.8% 로 떨어진다.** 어느 쪽을 쓸지는 용도가 정한다 — 착륙 지점 판정은
정밀도가, 지도 제작은 범위가 중요하다. 15°는 둘 사이의 타협이다.

`outputs/01_tradeoff.png` 의 왼쪽 그래프에서 두 선이 반대로 가는 것이 이것이다.

| 블록 | 값이 나온 픽셀 | Z 오차 중앙값 |

**작은 블록이 정확하다.** 달 지형은 크레이터와 그림자로 무늬가 넉넉해서, 작은
블록이 경사면을 덜 뭉갠다. 무늬가 적은 장면이라면 반대로 큰 블록이 필요하다 —
작은 블록은 애초에 대응을 못 찾기 때문이다.

**차이가 크지 않다는 점도 함께 봐야 한다.** 3에서 15까지 오차가 64 → 71 m 로
12% 움직이는데, 수렴각을 바꾸면 세 배가 움직인다. **파라미터보다 촬영 기하가
결과를 지배한다.** 5를 고른 것은 정확도를 조금 우선한 것이고, 유효화소가 중요한
용도라면 15가 낫다.

## 6. Unit Test 설계

과제 예시의 테스트(p.14)는 출력 크기와 자료형만 확인한다. 그것만으로는 수식이
틀려도 통과한다. **손으로 답을 낼 수 있는 조건**을 만들어 숫자까지 대조했다.

| 갈래 | 예시 | 검증 방식 |
|---|---|---|
| **해석해** | 평지를 수직으로 보면 깊이 = 촬영 고도 | 1e-6 이내 |
| | 기울기 tan(t) 사면의 법선 | 1e-9 이내 |
| | 태양이 머리 위면 밝기 = albedo | 1e-9 이내 |
| **불변식** | `B = 2·H·tan(수렴각/2)` | 상대오차 1e-12 |
| | `p_j = R·p_i + t` 가 실제로 성립 | 1e-12 이내 |
| | B와 d를 함께 2배 하면 Z 불변 | 스케일 모호성 |
| **왕복** | 깊이 맵 → 3D → 고도가 원래 값과 같은가 | 2 m 이내 |
| **전체** | 렌더링→정렬→정합→깊이 를 한 번에 | 시차 0.5 px 이내 |
| **회귀** | 렌더링한 두 장이 `f·B/d` 에서 겹치는가 | 실제 버그를 잡은 테스트 |
| | 수직 시점 두 대가 오른쪽을 뒤집지 않는가 | 두 번째 버그 |
| | 해를 마주 보는 사면이 밝은가 | 부호 실수를 잡은 테스트 |
| **경계** | 화소 크기 0, 수렴각 90°, 크기 불일치 | 예외 처리 |

**독립적인 경우는 `@pytest.mark.parametrize` 로 나눈다.** 잘못된 수렴각 네 가지,
잘못된 화소 크기 두 가지가 그렇다. 한 번에 루프를 돌면 첫 실패에서 멈춰
나머지가 실행되지 않고 어느 값에서 깨졌는지도 이름에 안 남는다.

## 7. 파이프라인을 만들며 잡은 버그

### 7-1. 렌더링이 시차를 밀어내고 있었다

처음 실행에서 Z 오차가 **1,245 m** 나왔다. 분해능이 450 m/px 인데 2.8 px 이라
잡음치고는 크고, 무엇보다 **오차가 한쪽으로 치우쳐** 있었다(부호 있는 오차 평균
−1,101 m).

| 확인한 것 | 결과 |
|---|---|
| 정렬 창 보정이 두 카메라의 주점을 어긋내나 | 아님 — 같은 양만큼 옮긴다 |
| `Z = f·B/d` 가 실제 투영과 맞나 | **정확히 일치** |
| 정렬 좌표계에서 직접 렌더링하면 | **오프셋 0.0 px** → 기하와 기준 깊이는 옳다 |
| `alpha` 를 바꾸면 오프셋이 | 2.0 / 2.6 / 3.6 → **초점거리에 비례** (각도 0.3°) |
| 점 번짐(splat)을 끄면 | +2.6 → **+0.6 px** |
| 화소마다 광선을 쏘면 | **−0.10 px** |

원인은 렌더러였다. 점을 화소에 던져 그리면서 위치를 **반올림**하는데, 그 오차가
표면 기울기 방향으로 쏠린다. 수렴 촬영의 두 카메라는 서로 반대로 기울어 있으므로
좌우가 반대로 쏠리고, 그 차이가 그대로 시차 치우침이 된다. 점 번짐은 깊이 버퍼에
3×3 최소값 필터를 거는 셈이라 표면을 카메라 쪽으로 당겨 이를 키웠다.

두 단계로 고쳤다. 번짐은 **빈 화소를 메우는 데만** 쓰도록 바꾸고, 흩뿌리기
자체를 **화소마다 광선을 쏘아 지형과 만나는 점을 이중선형으로 찾는 방식**으로
교체했다. **Z 오차 1,245 m → 66 m.**

`test_rendered_pair_aligns_at_the_disparity_the_geometry_predicts` 가 이것을
고정한다. 기하식만 대조하면 `P1`, `P2` 의 정의상 항상 맞아 떨어져 아무것도
검증하지 못하므로, **렌더링한 영상 자체**를 시차만큼 밀어 겹쳐 본다.

### 7-2. 수직 시점 두 대의 오른쪽이 뒤집혔다

카메라 자세를 만들 때 "위쪽"을 수직(0,0,1)으로 뒀다. 아래를 내려다보는 카메라는
시선이 거의 −Z 라 그 기준과 나란해지고, 외적이 0 에 가까워져 영상의 오른쪽이
시선의 미세한 수평 성분으로 정해진다. **두 카메라의 상대 회전이 15°가 아니라
180°로 나왔다.** 수평 기준(북쪽)을 주어 고쳤다.

### 7-3. 깊이 탐색 구간을 잘못 잡았다

`고도 ± 기복`으로 잡았는데, 정렬된 카메라는 수렴각의 절반만큼 기울어 있어
**지형이 넓으면 Z 가 화면을 가로질러 크게 변한다.** 티코(75 km 폭)에서 Z 가
±5 km 흔들려 옳은 시차가 구간 밖으로 잘려 나갔다. 지형 경계 상자의 여덟
꼭짓점을 정렬 카메라로 옮겨 실제 Z 범위를 구하도록 고쳤다.

### 7-4. 광선이 수렴하지 않은 채 값을 내고 있었다

고도장과 광선의 교점은 닫힌 형태가 없어 고정점 반복으로 푼다. 대부분 열 번
안에 기계 정밀도까지 수렴하는데, **지형 격자 밖으로 나간 광선**은 고도 표본이
가장자리 값으로 고정되어 값이 진동한다.

복원한 점이 실제로 고도장 위에 있는지 재 보니, 화소의 **10%가 잔차 1 m 를
넘었고 최악은 300 m** 였다. 반복 횟수를 다섯 배로 늘려도 줄지 않았다 —
수렴이 느린 것이 아니라 아예 수렴하지 않는 것이었다.

두 가지를 고쳤다. 반복이 끝난 뒤 t 를 한 번 더 갱신해 마지막 고도 표본과
어긋나지 않게 하고, **마지막 갱신 폭이 화소 크기의 1/100 을 넘으면 값을 내지
않는다.** "모른다"를 틀린 값으로 채우는 것보다 비워 두는 편이 낫다.

**잔차 최악 300 m → 0.04 m**, 1 m 를 넘는 화소는 0%가 됐다. 결과 수치는 거의
그대로다(RMSE 241 → 239 m). 채점 영역 밖의 화소가 대부분이었기 때문인데,
그래서 더더욱 **눈에 띄지 않는 결함**이었다.

## 8. 한계

- **밝기가 렌더링이다.** 기하는 실제 달이지만 그림자와 반사 특성은 실제 영상과
  다르다. 이 실험이 검증하는 것은 촬영 기하와 정합이다.
- **가림(occlusion)을 다루지 않는다.** 광선이 앞쪽 봉우리를 지나쳐 뒤쪽 지면에
  닿아도 그대로 받는다. 시선이 지면에 거의 수직이라 지금 조건에서는 문제가
  없지만, 수렴각을 더 키우면 확인이 필요하다.
- **값이 나온 픽셀이 72% 다.** 나머지는 대부분 크레이터 안쪽 그늘로, 두 사진에
  같은 무늬가 보이지 않는 곳이다.
- **고도 모델이 118 m/화소다.** 레이저 궤적을 격자로 편 것이라 매끈해서, 더 높은
  해상도 모델(LRO NAC DTM)보다 잔무늬가 적다.
- **수렴하지 않는 광선은 값을 내지 않는다.** 지형 격자 밖으로 나가는 광선이
  그렇다. 비워 두는 쪽을 골랐으므로 값이 나온 픽셀이 그만큼 줄어든다.
- **"대응이 없다"를 말할 수 없다.** 매처는 탐색 구간 안에서 반드시 무언가를
  고른다. 좌우에 같은 영상을 넣어도 21%의 화소가 값을 낸다(9절 ③).
- **촬영 자세를 정답으로 안다.** 우리가 정한 값이라 오차가 없다. 실제 궤도
  영상이라면 자세도 추정해야 하고, 그 오차가 결과를 흔든다.

## 9. 개선점

과제 요청내용 3번("변환된 3D 이미지의 시각적 결과를 분석하고 개선점을 도출")에
대한 답이다.

**① 수렴각을 용도에 맞춰 고른다 — 재 봤다.** 4절 표가 그 측정이다. 정밀도와
덮는 범위를 동시에 얻을 수 없으므로, 착륙 지점 판정이면 30°, 넓은 지도면 10°
쪽이다. 지금은 15°로 타협했다.

**② 그늘진 곳을 메운다 — 재 보지 않았다.** 값이 안 나오는 28% 는 대부분 크레이터
안쪽 그늘이다. **태양 각도가 다른 시점을 더 모으면** 줄일 수 있다. 실제 궤도
영상은 같은 지역을 여러 조명 조건에서 찍으므로 가능한 방향이다.

**③ 빈 곳을 "모름"으로 남긴다 — 절반만 했다.** 무늬가 옅은 곳은 값을 내지
않도록 관문을 걸었다(`stereo.texture_mask`). 화소를 2.6 %p 내주고 크게 틀린
화소를 3분의 1 줄였다(1 px 초과 0.99 → 0.69%).

**남은 절반이 더 크다.** 좌우에 **같은 영상**을 넣어도 화소의 21%가 값을 내고,
그중 96%가 1 px 이상 틀린다(중앙값 3,340 m). 관문을 걸어도 20%로 거의 줄지
않는다. 매처는 탐색 구간 안에서 반드시 무언가를 고르기 때문이다. 즉 이
파이프라인은 **"대응이 없다"를 말할 수 없다.** 화소마다 신뢰도를 함께 내야
하고, 착륙 지점 판정에서는 **모르는 곳을 피하는 것**이 정확도만큼 중요하다.

**④ 더 높은 해상도 고도 모델을 쓴다 — 재 보지 않았다.** LOLA 118 m 는 레이저
궤적을 격자로 편 것이라 매끈하다. LRO NAC DTM(2~5 m/화소)을 쓰면 잔무늬가 많아져
정합이 쉬워질 것으로 보이지만, PDS 원본 포맷과 전용 도구가 필요하다.
