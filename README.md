## [1차] 픽셀 단위 이미지 처리 → [`01_image_processing/`](01_image_processing/)

OpenCV로 위성 영상에서 특정 색상 화소를 검출하고, AI 학습용 전처리 파이프라인을
구성했습니다.

- **검출 범위를 측정으로 고쳤습니다.** 과제 예제의 빨강 범위(H 0~10, S≥120)는
  프랑스 Aigues-Mortes 염전을 0.41%밖에 못 잡습니다. 실제 화소를 재니
  H 7~11, **S 96~135** 로, 채도 하한 120에서 절반이 잘려 있었습니다. 범위를
  맞추니 검출량이 **2.15배**가 됐습니다.
- **이상치 임계값을 분포에서 정했습니다.** food101 1,000장의 밝기·면적비 분포를
  그려 왜도에 따라 기준을 골랐습니다. 기존 밝기 임계값 40은 1,000장에서
  **한 장도 걸러내지 못하고 있었습니다.**
- **정답 마스크 없이 검출 품질을 추정했습니다.** 100개 패치를 층화 추출해
  판정하고 윌슨 신뢰구간으로 정밀도 **88.0%** (76.2~94.4%)를 얻었습니다.
  능동학습 표본은 무작위 표본이 0개 찾은 놓침을 5개 찾아냈습니다.
- **증강을 학습 중 실시간으로 옮겼습니다.** PyTorch `Dataset.__getitem__`에서
  매번 난수를 뽑습니다. 사전 저장 대비 **60.8 GB** 절약.

## [2차] 2D → 3D 변환 → [`02_2d_to_3d/`](02_2d_to_3d/)

**달 사진 두 장으로 지형의 높낮이를 복원했습니다.** 착륙 지점을 고르려면 어디가
평평한지 알아야 하는데, 사진에는 색만 있고 높낮이가 없습니다. 같은 곳을 각도를
바꿔 두 번 찍고 두 사진에서 밀린 정도로 거리를 재는 **수렴 스테레오**입니다.
대상은 티코 크레이터, 정답은 LRO LOLA 레이저 고도계로 실제 측정된 고도입니다.

- **고도 오차 중앙값 30 m — 높낮이 차 5,376 m 의 0.56% 입니다.**
  시차 1픽셀이 450 m 를 바꾸는 촬영 조건이므로 한 픽셀보다 작게
  맞춘 셈입니다. 10곳 중 9곳이 82 m 안에 들고, 복원한 점은
  311,550개입니다.
- **1971년에 실제로 찍힌 사진으로도 확인했습니다.** 아폴로 15호 매핑 카메라가
  24초 간격으로 필름에 찍은 두 장을 같은 파이프라인에 넣었습니다. 사진에서 잰
  것만으로 계산한 카메라 고도가 **102.5 km** 로 아카이브 기록 100.9 km 와
  1.6% 안에서 맞고, 복원한 높낮이 차가 **2.74 km** 로 레이저 측정치
  2.72 km 와 1.01 배 안에서 맞습니다. 어느 쪽도 정답 고도를 보고 맞춘
  값이 아닙니다.
- **믿을 수 없는 곳을 정답 없이 걸러 냅니다.** 좌우 일관성 · 광도 잔차 · 정합
  봉우리의 뾰족함을 넣고, 그것이 실제 오차를 예측하는지 희소화 곡선과 AUC 로
  쟀습니다. 크게 틀린 화소를 골라내는 AUC 가 광도 잔차 0.94, 각도 간 편차
  0.97 입니다. 실제로 걸어서 RMSE 가 100 → 72 m 로 줄었습니다.
  재 보기 전에는 몰랐던 것도 나왔습니다 — **국소 대비는 무작위보다 나쁩니다.**
- **파라미터를 영상에서 정합니다.** 대비 하한을 절대값으로 박는 대신 영상의
  잡음에서 유도합니다(잡음 x 2 = 1.42). 블록 크기는 각도 간
  불일치와 재조명 일치도를 합쳐 정답 없이 고릅니다.
- **정밀도와 덮는 범위가 맞바뀌는 것을 측정했습니다.** 두 시선이 벌어진 각을
  10°에서 30°로 키우면 오차가 58 → 28 m 로 줄지만 값이 나온 화소가
  77 → 43% 로 떨어집니다. 각도가 다르면 성공하는 곳도 다르므로,
  네 각도를 합쳐 둘 다 얻었습니다.
- **렌더링이 시차를 밀어내던 버그를 테스트가 잡았습니다.** 처음 오차가 1,245 m 로
  한쪽에 치우쳐 있었습니다. 점을 화소에 던져 그릴 때의 반올림 오차가 경사
  방향으로 쏠렸고, 두 촬영 지점이 반대로 기울어 있어 좌우가 반대로 쏠린
  것이었습니다. 화소마다 광선을 쏘는 방식으로 바꿔 시차 치우침이
  **2.6 → 0.1 픽셀** 이 됐습니다.
- **Unit Test 79개.** 평지를 수직으로 보면 깊이가 촬영 고도와 같아야 한다,
  베이스라인이 `2·H·tan(수렴각/2)` 를 만족해야 한다처럼 **손으로 답을 낼 수
  있는 조건**으로 숫자까지 대조했습니다. 찾은 버그는 전부 회귀 테스트로
  고정했습니다.
- **남은 것.** 실제 사진 결과를 지도 좌표에 놓아 화소마다 채점하는 일과, 남긴
  값이 얼마나 정확한지를 말하는 일입니다. 크게 틀린 화소는 골라내지만 오차의
  크기까지는 못 맞힙니다.

## 실행

각 과제 폴더로 이동해서 실행합니다. 의존성은 폴더별 `requirements.txt`에 있습니다.

```bash
cd 01_image_processing && pip install -r requirements.txt
cd 02_2d_to_3d        && pip install -r requirements.txt
```

원본 데이터셋은 용량 문제로 저장소에 포함하지 않습니다(`.gitignore`의 `data/`).
각 README에 내려받는 명령이 있습니다.

## Git 워크플로

```
main ──●──────────────────●───────────────●
        \                /               /
         feature/image-processing (PR #1)
                          \             /
                           feature/2d-to-3d (PR #2)
```

`main`에 직접 커밋하지 않고 과제마다 feature 브랜치를 파서 PR로 병합합니다.
리뷰 전 코드가 기준 브랜치를 오염시키지 않게 하고, PR 단위로 변경 이력을
추적하기 위해서입니다. 리뷰에서 지적이 나오면 새 브랜치를 파지 않고 열려 있는
PR 위에 반영 커밋을 올려, 지적과 대응이 같은 PR 안에 남게 합니다.
